Chapter 5

Priya makes one change to Sidekick: the search now reads three passages instead of one. Same test cases, run again as version 2. The refund question that only got half an answer now gets both halves. The dashboard has to say whether that is really better, and it has to be right.

Change one thing, run again

That loop is the whole product: change something, restart, run the same test cases under a new version name. This example reads its search depth from an environment variable, so the same file is both versions.

{{example:versions_workflow.py}} 
python versions_workflow.py              # run it as version 1: one passage per question
TOP_K=3 python versions_workflow.py      # run it as version 2: three passages per question

On Windows PowerShell set the variable first: $env:TOP_K = 3. Everything else about the version, its notes and its groups, is saved with the run.

How versions are compared

An average is only fair when the versions answered the same questions. So ragevalkit compares them on the test cases they all ran:

  1. A case counts as the same only if its chat, turn, question and expected answer are unchanged.
  2. Adding a test case, or running an extra group, in a later version does not hide that version: it is judged on the cases the others also ran, and the card says so.
  3. If the shared cases are only a thin slice (say a 2-question smoke test next to 10-question runs), that version is left out and the reason is shown, so it cannot shrink everyone else's comparison.
  4. Versions that were stopped early, or failed on a shared case, are left out too.
  5. Each remaining version gets an overall score: answer quality and context quality, weighted 60/40 by default. If context quality was not graded for every version, all are compared on answer quality alone, and the card says so.
  6. Versions within a small tolerance (0.25 by default) of the best are tied, and the fastest of them wins.

What the card is telling you

The card saysWhat it means, and what to do
Recommended: v2 and the reasonThe best overall score among comparable versions; if several are tied, the fastest. Safe to ship on the evidence you have.
None yet, “Best so far: v1”No version reaches the minimum score of 5 out of 10, so nothing is recommended, but the best so far is named. A version that mostly gets answers wrong is not something to ship. Improve the pipeline, or check that the test cases ask about what it knows. Change the bar with recommendation_min_quality.
Latest v3 vs v2: answer −0.4 · context +0.1 · 1.2s slowerYour newest run against the recommended one, on the shared cases. It answers “should I ship what I just built, or stay on the pick?”.
“The latest run moved the recommendation from v1 to v2”Before the newest run, v1 was the pick. This run changed that.
Not compared: v3 (answer 10.0, context 10.0) ran 2 test cases and shares only 0…That version ran different test cases (typically because cases were edited, added or deleted), so it cannot be ranked against the others. Its own scores are shown so a good one is not hidden. Run the same test cases on both versions to compare them.
Left out: v4, 3 of the 6 shared test cases failedA version with failures on shared cases would look better or worse than it is. Open it, fix what failed, run it again.
“No version responds within 8s”You set a response-time ceiling and nothing meets it. The fastest is named.

Tuning the decision

OptionDefaultUse it to…
answer_weight / material_weight0.6 / 0.4decide how much answer quality and context quality count. Set material_weight=0 for assistants with no retrieval.
recommendation_tolerance0.25widen or narrow what counts as a tie. A wider tolerance favours speed.
recommendation_min_quality5.0raise the bar for what may be recommended at all.
max_response_timenonenever recommend a version slower than this many seconds.

The card also has two boxes to try tolerance and a time ceiling on the spot, without restarting. Archive a version to take it out of every comparison without deleting it; the recommendation updates straight away. It is calculated on each visit from the saved scores, so it can never be out of date.

Groups work the same way: pick a group on the dashboard to see which version is best for that group, which is how you notice that v2 is better at refunds but worse at shipping.
