Importing

  • You see what will be added, updated or skipped before anything is saved, with the row number and reason for every row that cannot be used.
  • Only the question column is required. Common header names (query, gold_answer, tags…) are recognised, and you can point any column at the right field.
  • Safe to repeat: importing the same file twice changes nothing; an edited answer becomes a new version of the existing case.
  • Rows that could not be imported can be downloaded with the reason next to each, fixed, and imported again.
  • Your own column names everywhere? column_map={"user_query": "question", "gold_answer": "expected_answer"} in serve().

Generating from documents

Test Cases → Generate from documents writes questions from your PDF, Word, text or Markdown files (up to 5 files of 50 MB). By default it writes three questions in each of four categories:

CategoryWhat it is
DirectThe answer is stated plainly in one place.
IndirectThe answer is in the document, but the question uses everyday words rather than the document's own.
Multi-partOne question with several parts, answered from different places.
Multi-turnA short conversation. Each follow-up depends on the earlier answer and cannot be understood alone.
  • Every answer comes with evidence: the sentences of your document that prove it, with file and page.
  • Nothing is added until you press Add. Questions are saved while they are being written, so closing the browser loses nothing, and you can edit or remove any of them first.
  • Nothing of the upload is kept, only the questions, answers and evidence snippets.
  • The text of the documents goes to the model you set with generator_model (the judge model by default). A local ollama/… model keeps it on your machine.
Tip

Generated questions are about your documents. Make sure your pipeline has those same documents loaded, or every score will be 0, and rightly so.

Groups

A group is a label. A case can carry any number of labels, and you add or remove them from the Test Cases page. Use them to run a slice (“only Billing”) and to see scores per slice on the version page. When you run several groups, a case in two of them runs once.

Follow-up questions need the turns before them, so by default a run also includes the earlier turns of every case you picked. The Execute dialog shows exactly how many cases will run, and lets you turn that off.

Deleting: a test case is removed for good (past versions keep their own copy of the question and answer, marked “Test case deleted”). A group is only hidden and can be restored. To keep a case but skip it in runs, mark it inactive.
