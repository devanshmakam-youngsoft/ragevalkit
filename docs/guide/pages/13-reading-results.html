Watch-outs and suggestions

At the end of each run the judge model writes plain-language findings: each thing to look at, paired with the next step to try. They name the group or question and use the numbers as evidence, rather than repeating the headline scores. Change what they look for with summary_prompt (Your judge).

Remarks: why a score is what it is

The Remarks column puts short coloured tags under each question, so you can see why before you open it: for the answer Correct, Minor gaps, Incomplete, Partly correct, Wrong answer, Made-up detail, Off topic or No answer; for the context Context complete, Context partial, Key text missing, Irrelevant context, Too much noise or Nothing retrieved. Rest the pointer on the tags to read the judge's full reason. Green tags are good, amber means look closer, red means something is wrong.

The judge picks the tags from this fixed list in the same call that grades the answer, so the words stay the same from run to run. A run saved before tags existed, or a custom judge that gives none, gets one tag worked out from the mark. The notes your pipeline wrote with note() moved into the question's own panel.

One question at a time

Click any row to open that question: the answer, the expected answer, the tags and the judge's reason for each score, the retrieved text, the sources found and missing, the time per step, and your notes. This is where wrong answers get explained.

  • Filter by group or score tier, and sort by score or time.
  • A question whose test case has been deleted since is marked, and keeps its own copy of the text.
  • Download an Excel report from the version page: a summary sheet, and one row per question.

Problems during the run

If something went wrong, the version page lists it in plain words, with Show technical details for the error and Download log for the full story. The same problem on many questions is listed once with a count. While a run is going you see a live count.

  • A failing pipeline function never stops a run: that question is marked failed, the reason is recorded, and the run goes on.
  • Logs are in the logs/ folder of your data folder (ragevalkit_data/ by default): server.log, one file per run, one per generation. Keys and passwords are hidden before anything is written.
Tip

Read Problems during this run before the scores. A run where half the questions failed has misleading averages.
